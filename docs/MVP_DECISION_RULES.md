# DETOUR 5주 MVP 기준과 의사결정 규칙

이 문서는 5주 안에 실제로 완성할 DETOUR의 범위를 고정한다. 수업 중 새 아이디어, API, 디자인 제안이 나와도 이 문서의 MVP를 자동으로 바꾸지 않는다.

## 5주 뒤 반드시 작동해야 하는 한 가지 경험

> 사용자가 출발지·도착지·남은 시간·예산·활동을 입력하면, DETOUR가 데이터와 설명 가능한 점수 계산을 바탕으로 가능한 우회 코스 TOP 3를 보여주고, 각 코스의 시간·비용·추천 이유·지도 위치를 확인할 수 있다.

## 반드시 구현할 MVP

1. 반응형 입력 화면
2. Frontend에서 FastAPI로 보내는 추천 요청
3. 20~50개 규모의 정제된 장소 데이터
4. 시간·예산·활동·거리 기준의 규칙 기반 filtering, score, ranking
5. TOP 3 카드: 예상 시간, 비용, 추천 이유
6. 지도 위의 후보 장소 또는 경로 표현
7. 배포 URL, README, 사용자 테스트 기록

## 이 MVP에 필요한 외부 연동

- 지도/장소/경로 API 하나: 실제 좌표·지도·이동 정보에 사용
- API key는 Frontend가 아닌 FastAPI 서버의 환경변수에서 관리

초기 화면과 추천 로직은 더미 데이터로 먼저 검증한다. 실제 API는 Week 2 이후, 위 MVP에 필요한 범위만 연결한다.

## 확장 기능 — MVP 완료 후에만

- 날씨 기반 실내·실외 가점
- 지역 단위 혼잡도 선호(조용함/활기참)
- 브라우저 현재 위치 자동 사용
- LLM으로 추천 이유 문장 다듬기
- Grok·인스타그램 등 트렌드 데이터
- 사용자 행동 기반 개인화

이 기능들은 핵심 추천 결과가 이미 작동하고, 현재 주차의 완료 조건을 해치지 않을 때만 추가한다.

## 새 아이디어를 평가하는 네 가지 질문

새 기능을 계획에 넣기 전에 반드시 모두 `예`여야 한다.

1. 이 기능이 없으면 5주 MVP의 핵심 경험이 깨지는가?
2. 현재 주차의 완료 조건에 직접 필요한가?
3. 이미 정한 기술 구조와 데이터 흐름 안에서 구현 가능한가?
4. API 권한·비용·보안·데이터 품질 때문에 일정을 크게 지연시키지 않는가?

하나라도 `아니오`라면 `확장 기능`으로 기록하고, 현재 계획과 일정은 바꾸지 않는다.

## 수업 과제와 5주 계획의 관계

수업의 90분 과제는 MVP의 **첫 번째 작은 단계**다.

```text
이번 시간: 더미 데이터로 입력 → 결과 카드
Week 2~4: API, 데이터, 점수 계산으로 실제 추천
Week 5: 지도·모바일 UX·배포·테스트
```

따라서 이번 시간에 `index.html`과 예시 카드로 만드는 것은 최종 MVP의 범위를 줄이거나 바꾸는 일이 아니다.
