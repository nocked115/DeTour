# 수업 기준 Week 1 브리프

2026-08-29 수업 사진에서 정리한 이번 주의 구현 기준이다. 다른 기획 문서보다 **이번 주 화면 구현 방식**에는 이 문서를 우선 적용한다.

## 사진에서 확인한 문구

### 오늘 만들 것

- `B형 — 오늘 만들 것`
- 예시: `인테리어 배치 · 여행 랜덤 미션 · 리포트 만들기`
- `만들 것: 입력 폼 → AI 한 번 → 결과 카드`
- `오늘 성공: 입력하면 결과 카드가 뜬다`
- `AI 키: 오늘은 결과 예시 2개를 넣어두고 화면부터 / 키는 다음 주`

### 화면 구현 방식

- `무엇으로 만드나 ① 화면`
- `프레임워크 = 큰 규모 앱을 위한 도구 모음. 우리에겐 과합니다`
- `CDN = 인터넷에 올려둔 파일을 주소 한 줄로 가져다 쓰는 것`
- `화면: index.html 한 파일로 / 설치도 빌드도 없음`
- `금지: React · Next 같은 프레임워크 / 설치·오류로 하루가 날아감`
- `디자인: Pico.css 한 줄 붙이기 / 클래스를 안 써도 버튼·표가 정돈됨`

### 데이터 구하는 다섯 가지

1. `RSS` — 주소 하나면 목록이 온다 · 뉴스·공지
2. `공공데이터 API` — 정부가 주는 진짜 데이터 · 신청 필요
3. `구글 시트 함수` — 표로 된 사이트를 함수 한 줄로 (사진 일부 흐림)
4. `손으로 20개` — 오늘 우리가 할 것
5. `파이썬 크롤링` — 4주 안엔 권하지 않음

### 첫 지시문 예시

> 빌드 도구 없이 index.html 한 파일로 만들어줘.
> 프레임워크는 쓰지 말고, 스타일은 Pico.css CDN.
> 데이터는 이 CSV 주소를 PapaParse로 읽어줘.
> 모바일에서도 안 깨지게.

## DETOUR에 적용하는 결론

이번 주에는 **실제 AI, 실제 장소 API, 크롤링, React/Next 설치를 하지 않는다.**

1. `index.html` 한 파일에 DETOUR의 입력 폼을 만든다.
2. 데이터는 우선 직접 만든 장소 20개로 시작한다.
3. 버튼을 누르면 예시 추천 결과 카드 2개가 뜨게 한다.
4. 화면은 모바일에서도 읽기 쉽게 만든다.
5. 실제 API와 AI 키는 다음 주에 검토한다.

### API/LLM 연결 결정

이번 90분 세션의 기준은 더미 데이터다. API 또는 LLM 연결은 선택 기능이 아니라 다음 주의 별도 작업으로 둔다.

- LLM은 현재 위치·날씨·이동 시간을 신뢰성 있게 제공하는 원천 데이터가 아니다.
- 카카오 REST API는 API key를 브라우저에 노출하지 않으려면 서버(FastAPI) 환경이 필요하다.
- 따라서 먼저 직접 만든 장소 20개와 예시 카드 2개로 핵심 사용 흐름을 완성한다.
- 화면이 완성된 뒤에도 시간이 남으면 API를 연결하지 않고, 다음 주에 연결할 API와 필요한 입력·응답 형식만 기록한다.

현재의 `detour-landing.html`은 이 목표를 앞서 구현한 프로토타입이다. 다음 작업에서 이를 `index.html` 중심의 수업 제출 형태로 정리한다.
