# 2주차 (8/29) · 첫 배포

## 🎯 오늘 하려던 것

빌드 도구 없이 `index.html` 한 파일로 "입력하면 결과 카드가 뜨는" 화면을 완성하고,
실제 URL에 올려 남에게 보여줄 수 있는 상태로 만드는 것.

원래 계획에서 배포는 5주차였다. 그런데 **가장 잘 막히는 단계가 만회할 시간이 없는 자리에
있다**고 판단해 2주차로 앞당겼다. 근거는 세 가지다.

- `index.html`은 정적 파일 한 개라 GitHub Pages 배포가 5분이면 된다
- 브라우저 위치 기능은 `file://`에서 아예 작동하지 않아 배포해야 테스트할 수 있다
- 배포하면 남은 4주 내내 "현재 상태"를 링크로 볼 수 있다

## ✅ 여기까지 됐다

### 화면

- 출발지·도착지·남은 시간·예산·활동을 입력하면 조건에 맞는 코스 2개와 추천 이유가 나온다
- 디자인 교체 — 형광 연두 포인트의 랜딩 페이지. 외부 CSS 없이 **파일 하나로 완결**
- 다섯 가지 상태 구현: 입력 / 찾는 중 / 결과 / 결과 없음 / 입력 오류
- 모바일 375px 확인 — 1열 배치, 가로 스크롤 없음, 버튼 54px

### 배포

- GitHub Pages로 배포. 폰에서 링크로 바로 열린다

### 서버 (계획보다 앞서 진행)

- FastAPI로 `/health`, `/places`, `/recommend` 구현
- 장소 20개를 `index.html`에서 `backend/data/places.json`으로 분리
- Pydantic으로 입력 검증 — `time`에 글자를 보내면 422와 함께 이유를 알려준다
- 브라우저가 실제로 서버에서 추천을 받아온다 (서버 로그로 POST 확인)
- **서버가 꺼져 있어도 화면이 깨지지 않는다** — 내장 20개로 대체

### 문서

- 5주 계획 재작성 — Day 1~7을 Session 1~3으로, 주 3~4회 3시간 리듬에 맞춤
- Figma 화면 상태 9개 정리 (각 화면이 언제 뜨는지, 어느 주차에 만드는지)
- 장소 유형별 체류 시간·비용 규칙표

## 🧱 막힌 것 / 어떻게 풀었나

### 다크 모드에서 제목이 안 보였다

노트북에서 `남는 시간을 나만의 우회로로.`가 보이지 않았다.

원인은 Pico.css였다. 사용자가 다크 모드면 Pico가 자동으로 어두운 테마를 적용해 **밝은 글씨 색**을
고른다. 그런데 나는 **배경만** 크림색으로 덮어썼다. 크림색 배경 위에 흰 글씨가 된 것이다.

색을 지정한 요소(`.eyebrow`, `.helper`)는 멀쩡했고, **Pico에 맡긴 요소만** 깨졌다.
테마를 고정하고 색을 직접 지정해 해결했다. 이후 디자인을 바꾸면서 Pico.css 자체를 제거해
같은 문제가 구조적으로 재발할 수 없게 했다.

> 배운 것: CSS 프레임워크를 부분적으로만 덮어쓰면 위험하다. 배경을 바꿨으면 글씨도 책임져야 한다.
> 그리고 내 화면에서 잘 보인다는 건 증거가 아니다.

### 90분이 남아도 20분짜리 코스를 먼저 추천했다

총 소요 시간이 **짧은 순**으로 정렬하고 있었다. "남는 시간을 나만의 우회로로"라는 제품 전제와
정반대였다. 남은 시간을 알차게 쓰는 순으로 바꿨다.

> 배운 것: 정렬 기준이 곧 제품의 주장이다.

### `92% Match`가 항상 92였다

`92 - index * 7`로 계산되던 하드코딩 값이었다. 입력을 뭘 하든 첫 카드는 92, 둘째는 85.
"설명 가능한 추천"이라는 제품 정체성과 정면으로 충돌한다.

삭제하고 `총 48분 · 7,000원 / 이동 7분 + 머무는 시간 41분 · 남은 60분 중 12분 여유`처럼
**사용자가 직접 검산할 수 있는 값**으로 바꿨다.

### 브라우저가 서버를 못 불렀다

CORS를 열었는데도 요청이 가지 않았다. 서버 로그에 `OPTIONS`만 찍히고 `POST`가 없었다.

원인은 `index.html`을 `file://`로 연 것이었다. 그렇게 열면 브라우저가 페이지에 출처 `null`을
부여하고 네트워크 요청을 막는다. `python -m http.server`로 띄워 `http://127.0.0.1:5500`으로
접속하니 해결됐다.

> 이때 하마터면 넘어갈 뻔했다. 화면에는 카드가 정상으로 떴기 때문이다.
> 대비책(내장 20개)이 조용히 작동한 결과였고, 서버 로그를 확인하고서야 알았다.
> **화면이 멀쩡하다고 연결이 된 것은 아니다.**

### 카카오맵 API 활성화 (미해결)

콘솔이 개편되어 `제품 설정 > 카카오맵` 메뉴를 찾지 못했다. 데브톡에 같은 문제를 겪는
사용자가 여럿 있다.

대신 **키가 필요 없는 기능부터 만들어 진도를 이어갔다.** `/health`, `/places`, `/recommend`는
카카오와 무관하다. 키는 `/geocode`(주소 → 좌표)를 만들 때 처음 필요하다.

> 배운 것: 막힌 것 하나가 전체를 세울 필요는 없다. 의존하지 않는 부분을 먼저 하면 된다.

## 현재 한계 (명확히 해둘 것)

서버 연결은 **내 노트북에서만** 작동한다.

```
지금:   github.io (전세계)  ✗  127.0.0.1 (내 노트북)
목표:   github.io (전세계)  ↔  배포된 서버 (전세계)
```

`127.0.0.1`은 "이 컴퓨터 자신"이라는 뜻이라, 배포된 사이트를 다른 사람이 열면
그 사람의 컴퓨터를 찾아가 실패한다. 그래서 배포된 사이트는 아직 내장 20개로 동작한다.

서버 배포는 Week 3 Session 3이다. 그때 `index.html`의 `API_BASE` 한 줄만 바꾸면 된다.
