# DETOUR 프로젝트 빠른 시작

이 문서는 처음 저장소를 열었거나 새 Codex 세션을 시작한 사람이 DETOUR의 맥락을 빠르게 파악하기 위한 안내서입니다.

## 무엇을 만드는가

DETOUR는 사용자의 목적지, 남은 시간, 예산, 원하는 활동에 맞춰 장소와 코스 TOP 3를 추천하는 반응형 웹 서비스입니다. 검색 결과를 많이 보여주는 대신, 현재 상황에서 왜 이 장소가 적합한지 설명하는 추천을 목표로 합니다.

## 현재 목표

5주 안에 아래 흐름이 실제 URL에서 동작하는 MVP를 완성합니다.

```text
사용자 입력 → FastAPI → 장소 데이터 → 추천 점수 → TOP 3 → 지도 표시
```

## 5주 로드맵

| 주차 | 핵심 공부 | DETOUR에서 구현할 것 |
| --- | --- | --- |
| 1주 | Frontend + 웹 구조 | 첫 화면 만들기 |
| 2주 | Backend + REST API | Frontend ↔ FastAPI 연결 |
| 3주 | DB 설계 + 데이터 파이프라인 | 장소 데이터 저장·가공 |
| 4주 | 추천 시스템 + 서비스 통합 | 개인화 DETOUR 추천 |
| 5주 | 서버 + 배포 + 운영 기초 | 지도, 모바일 UX, 실제 서비스 배포 |

## 핵심 추천 구조

```text
장소·경로 데이터
→ Feature Engineering
→ Normalization
→ 사용자 Weight
→ Score
→ Ranking
→ 추천 이유
```

처음에는 설명 가능한 규칙 기반 추천을 사용합니다. 복잡한 머신러닝, 회원 시스템, 다수의 지도 API 연동은 MVP 범위가 아닙니다.

## 협업 규칙

1. 현재 주차의 작은 작업만 먼저 구현합니다.
2. 변경 사항은 테스트하고 GitHub 커밋으로 남깁니다.
3. 환경변수와 API key는 커밋하지 않습니다.
4. 기술 용어는 학습 기록과 실제 코드에서 같은 의미로 사용합니다.
5. 사용자에게는 구현 결과와 함께 왜 그렇게 만들었는지 쉬운 말로 설명합니다.
